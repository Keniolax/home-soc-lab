# home-soc-lab

A small security operations lab that rebuilds itself from a git clone. One command starts a
SIEM, a victim host, and an attacker host. Nothing is click-built, so anyone can reproduce it.

## What runs in it

| Component | Image | Role |
|---|---|---|
| SIEM | Wazuh 4.14.7 (manager, indexer, dashboard) | Collects logs and raises alerts |
| Victim | Ubuntu 24.04 + Wazuh agent | The machine under attack |

## Quickstart

**You need:**

- macOS or Linux on `arm64` or `amd64`
- A container runtime: Colima, Docker Desktop, or Docker Engine 24 or later
- 8 GB of free RAM and 20 GB of free disk
- Ports **TODO** free

```bash
git clone https://github.com/Keniolax/home-soc-lab.git
cd home-soc-lab
make up
```

## Design decisions

> **Written from the project's decision log. Rewrite each "why" in your own words before you
> publish.** An interviewer will ask about these, and the answer has to sound like yours.

**Decision: Windows attack logs are replayed from public datasets, not generated by a live
Windows machine.**
*Alternatives considered:* a Windows 11 ARM virtual machine under UTM; emulating x86.
*Why:* the lab is built on Apple Silicon, where x86 Windows will not run. More importantly,
replayed logs clone and run on both `arm64` and `amd64`, so every reviewer sees the same
events. A live Windows guest would only work for other Apple Silicon users.
*Cost accepted:* Windows detections are written against a fixed dataset, so this lab cannot
test different Windows sensor settings. Linux attacks still run live.

**Decision: Wazuh is pinned to 4.14.7 by digest.**
*Alternatives considered:* the Elastic Stack; plain OpenSearch; a floating `latest` tag.
*Why:* Wazuh ships its own agent, decoders, and rule set, so the lab reaches real detections
sooner. Version matters more than usual here: Wazuh 4.14.7 publishes `arm64` images, but
4.10.4 is `amd64` only. An unpinned tag would break this lab on Apple Silicon without warning.
*Cost accepted:* Wazuh needs about 4 GB of RAM, more than a bare log store would.

**Decision: `make up` wraps the compose command.**
*Alternatives considered:* telling people to run `docker compose up` and a setup step by hand.
*Why:* the promise is one command. A README that hides a second step is not reproducible, it
is just untested.
*Cost accepted:* one more tool to install, though `make` ships with macOS and most Linux.

## What I chose not to build

- **No Vagrant.** Containers start faster and need less memory. The lab does not need full
  virtual machines.
- **No live Windows host.** See the first decision above.
- **No extra services.** The lab stops at four. This project is graded on whether a stranger
  can rebuild it, not on how large it is.
